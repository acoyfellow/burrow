# v5 security review 1

Scope note: base `0dd7b97` is not in this repo's history (`git diff 0dd7b97..HEAD` fails), so I reviewed the current v5 code on HEAD `04816f8` in the requested focus areas.

## Findings

### M1. A share link outlives its thread and then exposes a new thread created with the same name (medium)
`src/service.ts:153-159` (`remove`) calls `directory.remove(name)`. That only runs `DELETE FROM threads` (`src/directory.ts:213-215`). It leaves the `shares` row in place. `sharedView` (`src/service.ts:188-198`) checks only that the current owner of the name matches `share.owner`.
Exploit: the owner shares thread `deploy`. A link holder, inside Access, keeps the `/s/<token>` URL. The owner deletes `deploy`, believing that also revokes the link. Later the owner creates a new thread with the same name, for example through `create` with the same title slug, an explicit name, or `thread_create`. The old token now serves the new thread's full transcript, which may include secrets. A different owner cannot re-claim the name and leak their own data, because the owner check blocks that.
Fix: in `remove`, also `DELETE FROM shares WHERE name = ?`.

### L1. If the owner field is empty, owner scoping in thread-to-thread tools fails open (low)
`src/thread.ts:920-927` `ownerEmail()` returns `''` when the ledger and directory have no owner. The migration default is `owner TEXT NOT NULL DEFAULT ''` (`src/directory.ts:83`). With owner `''`, `thread_list`/`thread_read`/`thread_send` (`src/thread.ts:394-430`) match every legacy row whose owner is `''`.
Exploit: an old thread from before the owner column was added drives any other legacy thread. Thread names can be guessed. It can read them with `thread_read` and inject prompts with `thread_send`. This affects pre-migration data only.
Fix: throw when `ownerEmail()` is `''`.

### L2. web_fetch follows redirects with no host check (low)
`src/agent.ts:148-160`. `WEB_URL` checks only the scheme, and `redirect: 'follow'`. Worker `fetch` cannot reach RFC1918 or metadata addresses, so classic SSRF does not apply. It can still reach other Cloudflare-fronted hosts, including the coil origin and other same-account zones. Those calls carry no Access cookie, so this is limited. The 15 s timeout and 400 KB cap (`b2b5b09`) bound resource use, but nothing limits calls per turn. Prompt-injected pages can make the agent fan out fetches, costing spend and subrequests, but no data crosses owners.

### L3. Share page shows the model id and message count (low, informational)
`src/ui/shared.ts:26`. All fields are escaped with `escapeHtml`, which covers `& < > "`. Every interpolation is inside element text or a double-quoted attribute, and `m.role` is constrained. Strict CSP: `default-src 'none'`. No XSS.

## Checked, no issue
- **markdown XSS** (`client/src/view/markdown.ts:126-160`): no innerHTML, everything goes through foldkit virtual-dom text nodes. Links are limited to `^https?://` by both the regex and `safeLink`, with `rel=noopener noreferrer`. A `javascript:` URL cannot match. `lang` sits in a data-attribute, restricted to `[\w+-]`.
- **Share links** (`src/service.ts:124-133`, `src/directory.ts:144-181`): `known()` checks ownership. The token is 18 random bytes from a CSPRNG. Unshare is scoped to owner. The `/s/` route sits after Access admission and sends `no-store`, `noindex`, `no-referrer`.
- **thread_read/send/list** (`src/thread.ts:394-430`): owner check against the directory, self excluded, output wrapped as `<thread-data>` data. `thread_create` stamps the caller's owner.
- **StopAllLoops** (`src/service.ts:117-122`): `loopingFor(owner)` uses SQL scoped to owner.
- **DeleteThread / rename / archive**: `known()` checks ownership. `upsert` keeps the existing owner (`src/directory.ts:109`). See M1 for leftover shares.
- **Upload path traversal** (`src/index.ts:24-60`): the thread name is checked by regex. File names match `^[\w.-]{1,120}$` and cannot start with `.`, so there is no `/` and no `..`. Size is capped from both the header and the actual body. Ownership is checked through `known()`.
- **edit_file** (`src/agent.ts:345-378`): the path is not normalised, but it runs only inside the thread's own container, as the agent itself. Arbitrary paths are no wider than the existing `exec`/`write_file` tools. No crossing between owners or the host.
- **Notification click** (`client/src/command.ts:471`, `src/ui/sw.ts:24-38`): the URL is always built as `/t/${item.name}`, and thread names are `[a-z0-9-]`, so the URL stays same-origin. Only the app writes `data.url`, never a remote push.

VERDICT: PASS
